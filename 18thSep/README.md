Today I worked on building a <b>Patient Management System API using FastAPI</b>. I first created the <b>FastAPI application</b> and a <b>Patient Pydantic model</b> containing fields like <b>id, name, city, age, gender, height, and weight</b>. I used <b>Annotated</b> and <b>Field</b> to add descriptions, examples, and validation conditions to the fields, such as making age greater than 0 and less than 101 and making height and weight greater than 0. For the <b>gender field</b>, I used <b>Literal</b> so that only `male`, `female`, or `others` can be provided. I also created two <b>computed fields</b>, `bmi` and `verdict`, where BMI is calculated from the patient's height and weight and the verdict is generated based on the BMI value. I created a separate <b>PatientUpdate Pydantic model</b> for updating patient information, where I used <b>Optional fields</b> so that the user can update only the fields they want without providing all the patient information. I also added <b>JSON file handling</b> by creating `load_data()` and `save_data()` functions to read patient information from `patients.json` and save the updated information back into the file. For the API routes, I created a <b>GET endpoint for `/`</b> to return the name of the API and another <b>GET endpoint for `/about`</b> to return information about the project. I created a <b>GET `/view` endpoint</b> to load and display all the patient records from the JSON file. I then created a <b>GET `/patient/{pat_id}` endpoint</b> and practiced using a <b>path parameter</b> with `Path` to search for a particular patient using their ID, and I used <b>HTTPException with status code 404</b> when the patient is not found. For updating patient information, I created a <b>PUT `/edit/{patient_id}` endpoint</b> where I used both a <b>path parameter</b> and a <b>Pydantic request body</b> using `PatientUpdate`. I used <b>model_dump(exclude_unset=True)</b> so that only the fields actually provided in the update request are changed, and then I validated the updated information again by creating a new <b>Patient Pydantic object</b>. I also used <b>model_dump(exclude='id')</b> while saving the patient information back to the JSON data. For creating a new patient, I created a <b>POST `/create` endpoint</b> where FastAPI receives the patient data as a <b>Pydantic object</b>, validates it automatically, checks whether the patient ID already exists, and then saves the new patient information into the JSON file. If the patient already exists, I used <b>HTTPException with status code 400</b> to return an error. I also used <b>JSONResponse</b> to return specific response messages and status codes such as <b>201 for successful patient creation, 200 for successful update and deletion</b>. Finally, I created a <b>DELETE `/delete/{patient_id}` endpoint</b> where I used a path parameter to find the patient, deleted the patient from the dictionary, saved the updated data to the JSON file, and returned a successful response. Through this project, I practiced creating <b>FastAPI routes, GET/POST/PUT/DELETE operations, path parameters, query-related imports, Pydantic request models, field validation, nested/computed data, optional update fields, JSON file operations, model_dump(), HTTPException, and JSONResponse</b> while building a small patient management API.
